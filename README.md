# Dart 飞镖控制器固件

`Dart_v1` 是一套面向机器人飞镖机构的 STM32 固件。工程以 **STM32F411RET6** 为主控制器，当前已经完成舵机、蜂鸣器、电源按键、OpenMV 视觉通信、BMI088 IMU 驱动与电池电压采样等基础能力，为后续实现完整的飞镖动作流程提供硬件控制和状态采集基础。

本文档从两个角度介绍工程：

1. **单片机开发者视角**：芯片、时钟、外设、软件结构、通信协议和构建方法；
2. **设备使用者视角**：上电提示、按键关机、串口命令、舵机动作、蜂鸣器、视觉启动和电池查询方式。

> 当前版本处于硬件功能逐项验证完成、准备整合飞镖动作逻辑的阶段。本文内容以 `main` 分支当前源码为准。

## 3. 引脚与外设分配

### 3.1 引脚总表

| 引脚 | 外设/功能 | 用途 |
| --- | --- | --- |
| PA0 | TIM2_CH1 | 舵机 PWM 1 |
| PA1 | TIM2_CH2 | 舵机 PWM 2 |
| PA2 | USART2_TX | 用户控制/调试串口发送 |
| PA3 | USART2_RX | 用户控制/调试串口接收 |
| PA5 | SPI1_SCK | BMI088 SPI 时钟 |
| PA6 | TIM3_CH1 | 舵机 PWM 3 |
| PA7 | TIM3_CH2 | 舵机 PWM 4 |
| PA13 | SWDIO | SWD 下载与调试 |
| PA14 | SWCLK | SWD 下载与调试 |
| PB0 | GPIO 输出 | 外部电源关机请求，置高后保持 |
| PB1 | GPIO 输入 | 电源按键输入，高电平表示按下 |
| PB3 | GPIO 输出 | BMI088 陀螺仪片选 |
| PB4 | SPI1_MISO | BMI088 SPI 数据输入 |
| PB5 | SPI1_MOSI | BMI088 SPI 数据输出 |
| PB6 | TIM4_CH1 | 蜂鸣器 PWM |
| PC4 | ADC1_IN14 | 电池分压电压采样 |
| PC6 | USART6_TX | 与 OpenMV 通信 |
| PC7 | USART6_RX | 与 OpenMV 通信 |
| PC11 | EXTI11 | BMI088 加速度计数据就绪中断 |
| PC12 | EXTI12 | BMI088 陀螺仪数据就绪中断 |
| PD2 | GPIO 输出 | BMI088 加速度计片选 |
| PH0/PH1 | HSE | 25 MHz 外部晶振 |

> PB0 和 PB1 的具体电气行为依赖配套电源板。当前固件将 PB1 高电平视为按键按下，将 PB0 置高视为关机请求。

### 3.2 舵机 PWM

TIM2 和 TIM3 的定时器计数频率为 1 MHz，PWM 周期为 20 ms，即标准 50 Hz 舵机控制信号。

| 逻辑位置 | PWM 脉宽 |
| --- | ---: |
| 0° | 1000 µs |
| 90°/机械中位 | 1620 µs |
| 180° | 2000 µs |

`1620 µs` 是根据当前机械齿位校准得到的中位值，不是通用舵机的固定参数。当前 `SetServosPulse()` 会同时更新四路 PWM，因此四个舵机同步执行相同位置命令。

### 3.3 蜂鸣器 PWM

蜂鸣器由 TIM4_CH1（PB6）驱动，PWM 基频约为 4 kHz。程序通过不同比较值生成三级提示强度：

```text
低：10
中：20
高：40
```

蜂鸣器用于上电提示、关机交互反馈，也可通过 USART2 命令手动持续开启或关闭。

### 3.4 电池电压采样

电池采样使用 PC4 / ADC1_IN14：

- 12 位 ADC，满量程计数 4095；
- 参考电压按 3300 mV 计算；
- 单通道、软件触发、非连续转换；
- 采样时间 480 ADC cycles；
- 每次查询采集 16 个样本并求平均；
- 外部分压比按 4:1 计算。

换算关系为：

```text
电池电压(mV) = ADC平均值 × 3300 × 4 / 4095
```

理论换算范围约为 0～13.2 V。测量精度会受到 MCU VDDA、分压电阻误差和板级噪声影响；如需精确电量估计，应使用实测参考电压和分压系数进行标定。

### 3.5 BMI088 IMU

BMI088 通过 SPI1 连接，当前驱动配置包括：

- SPI Mode 3（CPOL 高、第二边沿采样）；
- SPI 速率约 6.25 Mbit/s；
- 加速度计量程 ±6 g、输出数据率 1600 Hz；
- 陀螺仪量程 ±2000 °/s、输出数据率 1000 Hz；
- 加速度计和陀螺仪分别使用数据就绪 EXTI；
- 启动后使用 1000 个静止样本估计陀螺仪零偏；
- 通过四元数和加速度反馈输出 Roll、Pitch、Yaw；
- 记录数据覆盖、SPI 错误和姿态更新次数，便于调试。

当前编译配置为：

```c
#define IMU_ENABLE 0U
```

因此 IMU 驱动源码仍参与编译，但主程序不会初始化 BMI088，也不会运行姿态任务，并会关闭 EXTI15_10 IRQ。需要重新启用时，将该宏改为 `1U`，上电后保持设备静止直至校准完成。

## 4. 软件架构

工程未使用 RTOS，采用“中断接收 + 主循环状态机”的裸机结构。

### 4.1 初始化顺序

程序进入 `main()` 后依次完成：

1. HAL 和 1 ms SysTick 初始化；
2. 100 MHz 系统时钟初始化；
3. GPIO、USART2、TIM2、TIM3、TIM4、SPI1、USART6、ADC1 初始化；
4. 启动四路舵机 PWM；
5. 启动蜂鸣器 PWM，并触发上电三声效果；
6. 启动 USART2 单字节中断接收；
7. 根据 `IMU_ENABLE` 决定是否初始化 BMI088；
8. 初始化 OpenMV 通信模块，等待用户命令启动识别流程。

### 4.2 主循环

主循环持续执行以下任务，不使用主动延时：

```text
IMU_Task（仅 IMU_ENABLE=1）
OpenMV_Task
电源按键状态机
蜂鸣器状态更新
USART2 命令执行
电池 ADC 查询与回传
串口溢出报告
IMU/OpenMV 调试信息回传
```

USART2 和 USART6 均采用中断收发。中断回调只完成字节入队、标志置位或发送状态更新，耗时操作放在主循环执行。

### 4.3 源码模块

| 文件 | 职责 |
| --- | --- |
| `Core/Src/main.c` | 初始化、主循环、电源按键、蜂鸣器、舵机和用户串口交互 |
| `Core/Src/adc.c` | ADC1 和 PC4 模拟输入初始化 |
| `Core/Src/tim.c` | 舵机与蜂鸣器 PWM 初始化 |
| `Core/Src/usart.c` | USART2、USART6 初始化及中断配置 |
| `Core/Src/spi.c` | BMI088 使用的 SPI1 初始化 |
| `Core/Src/bmi088.c` | BMI088 寄存器配置和原始数据读取 |
| `Core/Src/imu_task.c` | IMU 校准、采样调度、坐标映射和状态统计 |
| `Core/Src/attitude.c` | 四元数姿态更新及欧拉角计算 |
| `Core/Src/openmv_task.c` | OpenMV 启动状态机、环形缓冲区和目标帧解析 |
| `Core/Src/stm32f4xx_it.c` | STM32 中断入口 |

## 5. 使用者交互逻辑

### 5.1 上电流程

设备上电并完成初始化后，蜂鸣器播放由低到高的三声提示。每声持续约 180 ms，相邻提示起始间隔约 300 ms。

上电后：

- 四路舵机 PWM 已启动，但比较值初始为 0，收到位置命令后才设置有效舵机脉宽；
- USART2 已等待用户命令；
- OpenMV 串口已开始接收，但识别握手需要命令 `6` 启动；
- IMU 当前默认不运行；
- 电池电压在收到命令 `8` 时采样，不进行周期上报。

### 5.2 电源按键与关机

为避免误触，关机采用“长按 + 释放确认”流程：

1. 如果设备上电时按键仍处于按下状态，必须先释放；
2. 按住电源键至少 1 秒；
3. 达到长按时间后，蜂鸣器发出约 100 ms 提示音；
4. 释放按键，并保持释放状态至少 1 秒；
5. 蜂鸣器播放由高到低的三声提示；
6. 固件将 PB0 置高并持续保持，等待外部电源电路切断供电。

如果在确认阶段重新按下按键，释放计时会被取消，必须再次释放并保持 1 秒。

> 固件不会在 PB0 置高后继续执行应用逻辑，而是停留在死循环中，直到外部电源真正关闭。

### 5.3 用户控制串口

USART2 参数：

```text
波特率：115200
数据位：8
停止位：1
校验：无
流控：无
引脚：PA2(TX)、PA3(RX)
```

每条命令必须以 **CRLF**（`\r\n`，十六进制 `0D 0A`）结束。推荐直接发送下表中的完整字节序列。

| 用户操作 | 发送内容 | 十六进制 | 设备响应/动作 |
| --- | --- | --- | --- |
| 通信测试 | `1\r\n` | `31 0D 0A` | 返回 `ok\r\n` |
| 舵机端点切换 | `2\r\n` | `32 0D 0A` | 四路舵机在 0° 与 180° 之间交替，返回 `ok\r\n` |
| 舵机回机械中位 | `3\r\n` | `33 0D 0A` | 四路舵机设为 1620 µs，返回 `ok\r\n` |
| 蜂鸣器切换 | `4\r\n` | `34 0D 0A` | 持续蜂鸣开/关切换，返回 `ok\r\n` |
| 启动 OpenMV 流程 | `6\r\n` | `36 0D 0A` | 返回 `OpenMV start\r\n`，随后执行视觉握手 |
| 查询电池电压 | `8\r\n` | `38 0D 0A` | 返回 `Battery:x.xxV\r\n` |

电池 ADC 失败时返回：

```text
Battery ADC error
```

USART2 接收缓冲区为 256 字节。如果一条未结束的输入超过可用长度，缓冲区会清空，并尝试返回：

```text
UART RX overflow
```

发送端只有一个 128 字节异步缓冲区。如果短时间触发多条输出，发送忙时的新消息可能被放弃，因此调试工具应等待当前响应后再发送下一条命令。

### 5.4 舵机命令行为

命令 `2` 使用内部切换状态：

- 第一次发送：四路舵机到 0°（1000 µs）；
- 第二次发送：四路舵机到 180°（2000 µs）；
- 后续继续交替。

发送命令 `3` 后，四路舵机到机械中位（1620 µs），下一次命令 `2` 将切换到 180°。

动作前应确认机械结构不会因四路同步运动发生干涉。首次调试建议卸载高负载机构或限制供电电流。

## 6. OpenMV 通信

### 6.1 物理接口

OpenMV 使用 USART6：

```text
PC6  -> USART6_TX
PC7  -> USART6_RX
115200 8N1
```

### 6.2 启动握手

用户通过 USART2 发送 `6\r\n` 后，STM32 执行以下非阻塞状态机：

1. 向 OpenMV 发送 `0x11`，选择 Yaw/视觉任务；
2. 最多等待 6 秒，接收就绪标志 `FF 52 50 44 41 52 54`，即 `0xFF + "RPDART"`；
3. 发送唤醒命令 `0xAB`；
4. 等待至少 100 ms；
5. 发送普通模式命令 `0x55`；
6. 接收视觉目标数据；
7. 约 3 秒后发送一个以字符 `2` 开头的 15 字节记录名/时间标识。

主要错误码：

| 错误码 | 含义 |
| ---: | --- |
| 0 | 无错误 |
| 1 | UART 错误 |
| 2 | 等待 Ready 超时 |
| 3 | UART 发送超时 |

发生错误时，USART2 输出：

```text
OpenMV error:<错误码>
```

### 6.3 目标数据帧

STM32 接收 7 字节目标帧：

| 字节 | 内容 |
| ---: | --- |
| 0 | 帧头 `0xFF` |
| 1 | X 高字节 |
| 2 | X 低字节 |
| 3 | Y 高字节 |
| 4 | Y 低字节 |
| 5 | Width |
| 6 | Height |

坐标使用大端序组合。程序要求 `x < 320` 且 `y < 240`，随后计算目标中心：

```text
center_x = x + width / 2
center_y = y + height / 2
```

每收到一个有效新目标，USART2 输出：

```text
OpenMV x:<x> y:<y> w:<width> h:<height> cx:<center_x> cy:<center_y>
```

### 7.2 使用 Keil 构建

1. 安装 Keil MDK-ARM 5，并确保 ARM Compiler 5 可用；

工程启用了 HEX 输出。默认构建产物位于：

```text

MDK-ARM/Dart_v1/Dart_v1.hex
```

构建产物不纳入 Git。当前版本已经在 Arm Compiler 5 下完成全量重编译验证：

```text
0 Error(s), 14 Warning(s)
```

现有警告主要来自部分早期源码文件末尾缺少换行，以及 `IMU_ENABLE=0` 时 IMU 调试变量未使用；不影响固件链接和 HEX 生成。

### 7.3 使用 STM32CubeMX 修改外设

## 9. 当前限制与后续计划

当前版本主要用于底层硬件验证，尚未形成完整比赛动作逻辑：

- 四路舵机只能同步设置同一个脉宽，尚未抽象为独立机构动作；
- OpenMV 目标数据目前主要通过 USART2 输出，尚未闭环控制执行机构；
- IMU 默认关闭，姿态结果尚未接入飞镖动作决策；
- 电池功能提供即时电压，不包含电量百分比、低压告警和关机保护；
- USART2 命令协议是调试协议，尚无校验、序号或可靠重传；
- 尚未加入自动化单元测试，关键功能需结合真实硬件验证。

下一阶段计划基于现有舵机、视觉、IMU 和电池能力，设计飞镖行动状态机，并逐步完成动作编排、安全互锁、异常恢复和整机联调。

## 10. 安全注意事项

- 舵机和飞镖机构调试前，应确保运动范围内无人且无易损物；
- 首次运行新动作时建议拆除弹射载荷，使用限流电源并准备物理断电；
- 不要将高于 MCU 模拟输入允许范围的电压直接接入 PC4；必须经过正确分压，并确保 ADC 引脚电压不超过 VDDA；
- STM32 与 OpenMV、调试串口设备必须共地，并确认双方逻辑电平兼容；
- 修改舵机脉宽前应核对具体舵机和机械限位，避免堵转；
- PB0 关机输出依赖外部电源保持/切断电路，脱离配套硬件时不要假定它能直接关闭 MCU 电源。
